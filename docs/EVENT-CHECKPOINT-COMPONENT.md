# Event checkpoint component

RFEC2 preserves one supported event's owned state; it is not an ordinary-scene save admission policy. The composer must capture associated world state, preflight every component, rebuild links, publish the saved state and remove retired owners from the registry before gameplay resumes. Restoring a Switch does not replay linked effects or sounds.

Read-only inspection of installed `levels1.vpp/L1S1.rfl` found184 events across32 types. The original monitor-only component admitted11 records. The expanded type coverage admits160 records across25 types, subject to runtime settling and reference resolution. These are authored inventory counts, not successful save/load results.

Coverage adds common flags/mode for Slay/Remove/Invert, Goto/Goto_Player/Follow_Waypoints, animation requests, health/armor/message/grants, level transition requests, invulnerability, friendliness, AI mode, goals, attack, particles/gravity/alarm, Delay, push regions, When_Hit and weapon-related events. Supported Switch events preserve disabled state and activation count; authored limit/mode/unlimited must match. Settled UnHide events preserve the cooldown, rebased onto the restored clock. Existing death/threshold latches and cyclic count/enabled/deadline remain supported. All supported types preserve their removal latch and diagnostic death stamp.

The24 excluded L1S1 records are Play_Sound6, Look_At5, Explode6, Continuous_Damage2, Music_Start3, Music_Stop1 and Black_Out_Player1. Their external or transient behavior has not been admitted by this component. Unsupported types fail explicitly. Even supported types can have external effects: NPC navigation/animation, messages, alarms, particle/force state, inventories and pending level transitions need separate composer checks and persistence. Generic event flags alone do not restore those effects.

All pending common delayed dispatch is rejected. UnHide requests with pending on/off work are rejected. Authored nonzero delay alone is allowed when no dispatch is pending. Future delayed-dispatch support must preserve remaining time and source/actor UID mappings together; this version does not manufacture that state.

Read-only, stable mapping callbacks convert non-sentinel source/actor handles into authored UIDs on capture and resolve them to fresh handles on restore. Zero and `UINT32_MAX` remain distinct tagged sentinels. Missing mappings reject before publication. The no-mapping convenience functions admit sentinel references only. The caller must resolve UIDs for the correct level and object category; the supplied32-byte identity binds the level and authored settings. Removed referenced objects need an explicit higher-level policy rather than guessed handles.

RFEC2 is192 bytes, all integer fields little-endian. Header0..63 contains magic/version/length/FNV checksum (checksum bytes treated as zero), UID, type, identity32 and reserved8. Payload offsets:64 flags,68 mode,72 death-fired,76 diagnostic death-time;80..100 cycle remaining/period/limit/count/enabled/unlimited;104 threshold,108 threshold-fired;112 retired;116/120 source tag/value;124/128 actor tag/value;132 reserved;136..152 Switch disabled/limit/unlimited/activations/mode;156 UnHide remaining;160..191 reserved. Reference tags0/1 represent zero/`UINT32_MAX` with zero value; tag2 holds an authored UID. Inapplicable fields are zero. RFEC1 payloads explicitly reject rather than silently reinterpret.

Focused test source covers actual cycle ticking, actual Switch activation, settled UnHide cooldown, common-type round trips, regenerated references, unresolved-reference atomic rejection, pending-work rejection and composer-side registry retirement. This extension has not been built or run by its author; parent integration owns validation. No original executable execution or screenshots were used.
