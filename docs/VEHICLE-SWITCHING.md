# Ground vehicle switching

The current implementation permits ordinary Use to transfer the active runtime between nearby parked, unoccupied Drillers, APCs or Jeeps of the same class, or another ground class with its required resource pack prepared. Each authored vehicle retains its UID and generation handle; checked registry exchange changes which runtime represents it. A bounded level-local bank retains rigid state, ammunition, firing cadence/random state and aiming state. Passive health and damage remain authoritative while parked.

Admission rejects other occupied or linked owners, active or authored movement routes, moving chassis, pending firing/effects, grouped hosts and obstructed boarding paths. Ground cross-class handoff and submarine-to-ground runtime handoff are implemented; submarine save continuation and Fighter switching remain open (see `VEHICLE-SUBMARINE-SWITCHING.md`). These are explicit first-pass constraints, not complete campaign vehicle support.

The narrow living-driver exception now keeps the exact authored stationary
Jeep driver in canonical passive seats while another Jeep is selected. Ordinary
save/fresh-load, return gunner boarding and host-qualified parked-wreck release
pass stock64MiB Xbox; see [living passive drivers](VEHICLE-PASSIVE-DRIVER.md).
Moving/route-owned and occupied cross-class transfers remain rejected.

Ordinary saves now write an outer RFSW1 vehicle wrapper: a 24-byte header identifies the selected authored UID/profile and passive slot order, followed by the existing vehicle payload and explicit 320-byte parked-state rows. Fresh loading validates source identity before selecting the saved host, admits the complete passive UID set before reordering, and restores parked ammunition/RNG, rigid state, aim and firing state after RFVA/RFPV publication. Runtime handles and pointers are reconstructed. Unswitched saves retain their existing format. Direct in-session restores and legacy RFCP saves remain rejected with a parked bank; normal fresh-scene quickload is supported. Stock-64-MiB Xbox report `artifacts/xemu/vehicle-switch-save-20261003-171018/report.json` passes a 350-frame source save and 140-frame fresh-load continuation: active Jeep B is selected before binding, both ammunition/RNG states match exactly, and ordinary exit/reboarding restores parked Jeep A. The source writes 15,768 bytes; the harness restores the original disc afterward.

Validation: the checked registry-exchange unit passes and the NXDK Xbox build succeeds. Stock-64-MiB Xbox report `artifacts/xemu/vehicle-switch-20261003-165718/report.json` passes 480 frames: three ordinary boardings, two exits, two switches, stable handles, exact parked pose/vitals and independently spent ammunition retained on return. The fixture restores the disc afterward. Driller/APC switching is compiled but not separately exercised. No visual or campaign-playthrough claim is made.

Wreck recovery: a settled, fully vacated destroyed host can yield its active runtime to a healthy same-class vehicle. The old wreck no longer competes as a usable target; the new host receives its own alive state, and releasing Use clears the dead host's old input latch. Pending destruction/ejection, movement, fire and dependency gates remain. Stock-64-MiB Xbox report `artifacts/xemu/vehicle-wreck-switch-20261003-171732/report.json` passes 350 frames: occupied Jeep A is destroyed by the ordinary Slay event, the living player exits, then boards and fires from Jeep B while A retains its original handle and destroyed health. Wreck save continuation and audiovisual output were not separately checked.

Released authored drivers: an exact inactive Jeep binding no longer permanently prevents switching. The actor must have no parent link or seated AI action, all live seat/driver slots must be clear, and both endpoint generations must resolve. Unknown authored references still block. Fresh switched saves reconstruct passive-host inactive bindings only from source-validated RFNS actor/host/tag records, without seating or moving the actor. The RFNS format is unchanged. Stock-64-MiB Xbox source `vehicle-released-driver-20261003-172438` completed 350 frames and wrote a 16,904-byte ordinary save. The initial checker incorrectly required RFNC12; the encoder uses RFNC10 for this inactive corpse, and corrected full source validation passed without replaying it. Fresh-load report `artifacts/xemu/vehicle-released-driver-20261003-172706/report.json` passes 140 frames, retains the dead detached miner and inactive RFNS relationship while Jeep B is active, then returns normally to Jeep A. Living voluntary NPC release, other vehicle classes and audiovisual output remain unverified.

Cross-class groundwork: startup now calls an explicit-profile resource loader with the previous model/weapon budgets and defaults. Stock-64-MiB regression report `artifacts/xemu/vehicle-switch-20261003-173127/report.json` passes the existing 480-frame Jeep A-to-B-to-A boarding/firing sequence after extraction. `tools/xemu_vehicle_mixed_types.py` now verifies ordinary Jeep7629-to-APC3303 switching and primary fire on stock64MiB Xbox (report `vehicle-mixed-mixed-20261003-175927`). Resource packs retain extras, chassis/material ownership transfers once, and collision/support/entry pointers are rebound for the target class. RFSW2 adds per-parked-row profiles while retaining RFSW1 compatibility. Stock64MiB Xbox fresh-load report `vehicle-mixed-save-20261003-181011` restores occupied APC ammunition994/RNG3750785579 and parked Jeep ammunition996/RNG1030492215, then ordinary exit/Use returns to Jeep driver control; see `VEHICLE-CROSS-CLASS-OWNERSHIP.md` for the implementation and evidence.
