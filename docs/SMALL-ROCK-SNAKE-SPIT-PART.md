## Ownership, optionality and bounds

`scene_spit_visual_accept(i,&shot,frame)` is called only after the mechanics publishes a real delayed release. It copies the accepted flight and complete source handle and allocates a monotonically increasing64-bit visual ticket. A reused slot is cleared even if its old trajectory was not drawn. Ticket exhaustion simply omits the visual. Pending windup does not emit flight particles. A queue ticket prevents a queued old-flight ID from drawing a replacement flight after reset/reuse during callbacks.

`scene_spit_visual_tick` follows the shared Spit flight tick, once per simulation frame. Repeated frames do not age or emit. Nonconsecutive frames, mismatched copied ownership or invalid numeric/room results discard the affected visual; no deferred catch-up runs against a later trajectory. Terminal flights immediately clear their particle state. Ordinary owned-model destruction486670→489fc0→502b10→5028f0→504620→54b570→542b60→5431f0 frees the original PART arrays; the unrelated drain-capable stop API does not justify detached projectile tails. The mechanical reset hook clears all unsaved visual state on the same successful-load/world/life boundaries. Mechanical active-flight save guards already cover all surviving visual owners; no extra save rows or tail admission are needed.

Shared original resources have a96KiB admission ceiling including fixed runtime state, both texture images, retained materials and bounded loader scratch. The fixed16×2×27 runtime slots require about36KiB before resource headers on32-bit Xbox; the two decoded images add32KiB. Exact residency/peak values are derived from `sizeof` and subordinate owners at admission and remain to be observed on Xbox. No per-frame allocations occur, and the existing particle queue is reused rather than resized.

Startup resource admission is expressly optional. Parent ignores only this visual-open return and retains its diagnostic status; missing/unsupported assets get no replacement and cannot disable Small Spit or reject an accepted finite-ammo shot. Partial resources are released. Visual tick, queue and draw errors remain in `rf_scene_spit_visual[7]` and never propagate into mechanics. Existing render entries are enqueued before Spit, so visual pressure does not displace them. Accepted ammo is never refunded or debited by this code.
