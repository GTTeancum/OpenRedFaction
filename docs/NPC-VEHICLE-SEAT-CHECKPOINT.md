# Authored NPC seat continuity (RFNS1)

Integrated and Xbox-built. The occupied turret native continuity check is recorded in NPC-TURRET-SEAT-SAVE-CHECK.md. This preserves the physical seat and turret-control association without replaying gameplay bind/unbind callbacks, changing saved actions, or resetting turret fire cadence.

## Files and format

`src/diagnostic/scene_npc_seat_checkpoint_decl.inc` contains early opaque declarations; include it immediately before `scene_npc_checkpoint_capture.inc` in `scene.c`. Include `scene_npc_seat_checkpoint.inc` immediately after `scene_npc_seat_bind.inc`, where driller/seat/operator definitions and earlier restore types are available. Use `scene_npc_seat_checkpoint_bytes(stage)` rather than accessing the opaque stage in the early world loader. No large existing include needs moving.

The vehicle section becomes `RFTU2(RFTU1(RFNS1(RFVA(vehicle + RFVR))))`, omitting absent layers. RFNS1 header is 16 bytes: magic `RFNS`, version 1, inner-byte count, row count. Each 24-byte LE row contains actor UID, host UID, signed tag index, kind (1 Jeep, 2 turret), active (0/1), and owned-host-control-flag (0/1). No registry handles or pointers are serialized. The inner payload may be empty on turret-only levels. Maximum wire overhead is 3,088 bytes.

All successfully authored binding records are retained, including detached records. Thus a saved dead/removed operator does not silently regain its fresh authored seat. Unknown authored references remain unresolved; this wrapper neither invents hosts nor expands runtime admission. RFNS absence is accepted on levels with no resolved authored bindings. Legacy saves on an occupied level remain explicitly unsupported (`RF_NOT_FOUND`), rather than preserving fresh seats over unrelated saved NPC state.

## Shared integration hooks

1. **Capture admission.** In `scene_npc_checkpoint_capture.inc`, retain the linked-handle rejection unless `scene_npc_seat_checkpoint_actor(o->registration.handle)` is true. Apply the same narrow exception to the body-pitch/roll rejection: the saved host and tag reconstruct the full basis. Do not relax occupant count, arbitrary attachments, pending orders, reload or other existing guards. In `scene_turret_checkpoint_capture_row`, allow nonzero occupant count only when `scene_npc_seat_checkpoint_host(o->handle)` proves the actual pair; linked host parents remain rejected. Add mode 13 to the syntactic whitelist in `src/core/npc_checkpoint.c` and update the header comment; composed restore below rejects every orphan mode 13.

2. **Capture wrapper.** In `scene_world_snapshot_capture_mode`, after RFVA wraps vehicle bytes and before RFTU1 capture, call `scene_npc_seat_checkpoint_capture(buffer+at, capacity, bytes, &wrapped)` and replace `bytes` with `wrapped`. The wrapper checks real generation-resolved ownership and the associated operator row before writing.

3. **Read order.** In `scene_world_load`, add opaque `scene_npc_seat_checkpoint_stage *seats=NULL`. Peel RFTU2, RFTU1, then call `scene_npc_seat_checkpoint_prepare(vehicle_data,vehicle_bytes,budget-cost,&seats,&vehicle_data,&vehicle_bytes)`, charge `_bytes(seats)`, then peel RFVA. Move the existing read-only vehicle decode/RFVR block before world/NPC staging. Call `_hosts(seats,turrets,vehicle_present?&vehicle:NULL)` before world staging. This derives expected actor basis/position from the **candidate saved** host, not the fresh spawn. Alive occupied rows require a living unhidden host and no simultaneous player occupancy.

4. **Carry an explicit stage.** Add `const scene_npc_seat_checkpoint_stage *seats` to `scene_world_restore_stage` and the composed `_prepare_with_passive` arguments. Pass it through `scene_npc_checkpoint_restore_prepare_mode`; legacy/component wrappers pass NULL. Immediately after `rf_look_orientation(angles,e->basis)` call `_basis(seats,rows+i,e->basis,&seated)`, before eye/tensor/body reconstruction. For admitted seats clear candidate body support/fall flags `1u|0x400000u`; bypass only the final `placement.count && support.material==-1 && fresh body was falling/supported` clause with `!seated`. Keep all other room/support/position checks. This helper rejects orphan AI13, active movement/combat/queued shots/script animation, hidden/dead/retired actors, mismatched seat position, and unsaved independently aimed basis locks.

5. **Placement.** In `scene_world_restore_place`, immediately after extracting UID and incrementing `placement_next`, call `_place(s->seats,uid,&world,placement,room,support,&handled)`; return its status when failing or handled. It admits exact saved seat basis/position through existing candidate-world static/mover/prop clearance and room checks, lifting only the floor-contact requirement and returning no ground support. It does not use the authored-overlap bypass.

6. **Own-Jeep pair contact.** `scene_world_vehicle_other_pair` currently allows only the player to overlap its host. Add the explicit stage/host UID to its pair context. For `i==0 && j>=2` allow the own-seat pair only if `_owns(seats,campaign_authored_vehicle_uid,npcs->entries[j-2].saved.uid)` proves it. Keep all other vehicle/NPC collisions checked. The staged actor is already required to occupy the exact tag pose.

7. **Fresh owner occupancy guards.** Both `scene_vehicle_checkpoint_read` and `scene_vehicle_checkpoint_parked_owner` currently reject `entry.host.driver!=UINT32_MAX || entry.occupant!=-1`. Preserve all player/session/burn guards, but allow those two words when `_host(entry.registration.handle)` proves a real authored NPC seat. This is an exception for the existing owner only; saved seat admission still requires RFNS. It lets all fallible parked publication admission complete while the fresh seat remains valid. Existing Jeep parked publication changes physics/control values but preserves physical occupant/driver words.

8. **Cross-admission and publication.** After ordinary NPC/turret validations call `_admit(seats,world->npcs)`. It checks current generation handles/pairs and every staged row, including orphan AI13 rejection even for a NULL seat stage. After the existing successful parked-vehicle publication and **before** the first assignment-only world publication, call `_detach(seats)`. Then assign movers/passive/clutter/NPC/turret as today; call `_assign(seats)` immediately after turret assignment. This phase publishes only prevalidated physical links/occupant words and operator control rows, without callbacks or allocation. Inactive saved rows remain inactive. Fresh linked-handle state never replaces the staged state, and snapshots used by final owner validation are not changed until all validations pass. Keep later player-occupied publication in its existing place; an active saved NPC seat forbids simultaneous player occupancy.

9. **Cleanup.** Call `_close(&seats)` in world-load cleanup. No global admission stage, borrowed mutable decoder buffer, or serialized registry handle is used. `rf_scene_npc_seat_checkpoint[6]` reports captures, restores, rows, active rows restored, candidate placements and reserved error word. Operator telemetry is retained when assignment replaces its control bank.

## Scope and remaining check

This first slice supports the installed Jeep driver and three stationary-turret operators, plus detached/dead saved bindings. Arbitrary boarding, generated Auto Turret child ownership, independently rotating passengers, and player/NPC dual-seat Jeep possession remain separate. No build/runtime was run by the helper; one bounded Xbox occupied-level ordinary save/fresh-load check is needed after integration. The existing generated turret companion must peel its outer RFTU2 before the sequence above.
