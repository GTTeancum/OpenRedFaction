# Clutter damage scene wiring audit (2026-09-16)

Scope: read-only audit of current scene and retained original evidence; no scene changes or runs. New clutter_gameplay/clutter_damage modules provide parsing/arithmetic only. Rendering a prop and retaining its collision resource currently does not make it a weapon recipient.

## Existing entry points and concrete gaps

- `campaign_clutter_bodies_open` creates registered base owners, then assigns state.class_index/definition. It still leaves base health100 rather than authored80 for all three testbed lamps. Use existing full-factory initialization policy (negative life =>100 and genericbit4, otherwise authored life; armor0), without allocating another owner. Do not infer protection from visual material.
- `campaign_clutter_registered(handle,&slot,&model)` already validates full generation-bearing registry handle, registry pointer equality to owner.state, placement/model bounds and attached shared-model token. Reuse this for every damage commit. Never use a raw level UID, index or stale borrowed owner pointer as authority.
- `rf_clutter_state` has health, armor, flags, definition and class_index but **no killing_type**. `word_a8` is not evidence for original+2ac. Add a named int32 field or a bounded per-placement int32 sidecar (506 entries=2024 bytes), not an alias to an unrelated timer/slot. This must survive from damage dispatch to deferred update. A one-shot update guard must use simulation frame ownership, not rendering frequency.
- `campaign_combat_tick` only selects NPC body spheres in its per-pellet loop, then calls `rf_scene_npc_damage`. New clutter needs a competing nearest typed recipient before damage dispatch. `combat_body` can broad-phase bounds/spheres, but ordinary props have fallback spheres: do not advertise those as exact model hits. Existing `rf_scene_clutter_collision_query`/`rf_scene_clutter_visibility_view` expose retained model geometry and world pose for a precise model segment adapter; they presently service probes/glare queries, not this shot selection. Preserve NPC-versus-clutter nearest ordering and CF0x27 world obstruction. A world obstruction must block a prop behind it.
- `scene_rocket_sweep` currently queries only `rf_geometry_collision_world_sweep_liquid` and always writes contact.object=UINT32_MAX. Connecting blast recipients alone enables nearby explosions to damage lamps but does **not** enable direct projectile impacts against lamps. A later mixed sweep must compare model/prop contact with world/liquid fractions and preserve room/normal/object identity; keep this separately visible in the milestone.
- `scene_rocket_blast` enumerates NPCs plus player only. Add typed registered clutter iteration using each retained body.state.position with the existing `scene_blast_amount` CF5 cover/falloff policy, then invoke a clutter-specific adapter with type3 and protection override0. Do not use actor damage effects or actor death/drop dispatch for props.

## Small ordered patch sequence

1. At class preparation, parse one selected class span per active class using `rf_clutter_gameplay_read`, retain the compact gameplay sidecar, and resolve break effect owners separately. Reuse current class.timer and vclip particle_count; do not replicate them506 times. Before enabling damage, establish supported ordinary no-corpse/no-special-glass readiness and real named resource ownership. Keep unsupported props present and expose their readiness failure. Initialize authored owner health/protection once during `campaign_clutter_bodies_open`.
2. Add `campaign_clutter_damage(handle,amount,type,override,...)`: validate through `campaign_clutter_registered`; validate class_index/definition and active sidecar; gather health/flags/killing type; call pure `rf_clutter_damage_receive`; publish only its validated candidate. This is the one commit point shared by blast and later hitscan. The generic damagedbit is set before protected rejection, as original4892c0 does. Do not skip protected candidates before the adapter if damaged-bit parity is desired. No allocation, release, effects or class-timer mutation inside this function.
3. First connect `scene_rocket_blast` with explicit clutter candidate/admitted/lethal telemetry; retain existing player/NPC loop and cover semantics. Separately connect `campaign_combat_tick` typed nearest recipient/model segment adapter. Treat Riot Shield class as excluded until its specific410270 continuation is supported; its normal factory class index already exists as campaign_riot_shield_class.
4. Add one deferred clutter health-break/retirement pass in the **simulation block before `campaign_glare_retirement_pass`**, after outstanding damage producers for that tick. Current `campaign_combat_tick` is invoked from `scene_world_prepare`, while glare/attachment passes are in scene_frame's guarded simulation block: check actual invocation order before wiring. It is valid for damage delivered later to be consumed at the next simulation boundary, matching a deferred phase; it is not valid to process it repeatedly when preparing the same frame. Do not free owners while iterating a borrowed glare/collision snapshot.
5. For each supported ordinary dead owner, prepare world effect position from class local offset and owner matrix before release; query real particle_count. When class.timer expires, dispatch the bound effect then reset the shared deadline by50 game milliseconds even if the service returns a failure-like/no-emission result. Positive particle_count suppresses ordinary mesh debris independently of cooldown/effect success. Then mark retirement; create authored mesh debris only when count<=0 and its resources are supported. Keep sound/emitter/light handles owned by the new effect/debris owners. A live-positive already-marked GeoMod prop skips all health-break emission and just retires. Class timer must survive freeing any one instance.
6. Once marked and no borrowed snapshot exists, clear its `campaign_attachment_nodes[slot]` pointer-bearing record, close owned per-instance sounds/emitters if introduced, remove any retained collision-pair memberships, then use `rf_clutter_shared_static_base_close(shared+model,bodies+slot,registry,object_list)`. This validates and releases body/model-instance reference/list/registry while preserving immutable shared resource and other instances. Do not call whole-level `campaign_clutter_bodies_close`, which closes all glares/props and frees shared arrays.
7. Publish a tombstone preserving placement indices. `scene_clutter_draw` currently treats NULL owner with a valid model slot as RF_FORMAT; either explicitly skip NULL owner or set only that placement's model slot UINT32_MAX after successful close. Do not clear the shared model resource. Audit all direct placement consumers, not just rendering. Then call existing `campaign_glare_retirement_pass`: its parent lookup sees the now-absent handle, releases child glare and clears its attachment node. `campaign_attachments_pass` already skips NULL parents and rebuilds. Keep unrelated instances and their glares alive.

## Effect and collision limitations which must stay explicit

`scene_rockets_tick` currently orders rocket impact visual, impact sound, blast damage, then GeoMod admission/publication. Preserve this independent impact sequence; a dead lamp's later authored break is another effect. `scene_impact_start` is explicitly a six-central-emitter Rocket Launcher recipe and cannot simply be relabeled yellboom. Shipped yellboom uses code_explode, named explosion "rocket hit", foley "light break" and60 hotspark particles. Bind its actual vclip resources and dispatch that contract. It suppresses genericlight mesh debris. A corpse class is replacement clutter, never an invented pickup.

The renderer checks genericbit2; direct `rf_scene_clutter_collision_query` still accepts any registered owner and does not itself rejectbit2. Add liveness filtering at new recipient/model-collision enumerators immediately after marking; after registry removal it naturally returns NOT_FOUND. Existing actor collision pair lists are transient actor-oriented code; no persistent generic clutter pair owner was established by this audit. If the new adapter retains such lists, remove both endpoints before free, following original48c9f0. Merely freeing collision geometry would destroy all instances sharing it and is wrong.

## Required acceptance before claiming live break support

- Actual lamp80 health:79 effective damage survives, next1 captures type and retires at deferred boundary; rejected stale handle never mutates a replacement owner.
- Two same-class lamps sharing a model/glare resources: first and second lethal hits inside50ms both disappear and lose owned glares, only first emits gated authored effect/audio; third at50ms emits. Shared model remains usable and reference count drops once per retired owner.
- Positive-health GeoMod mark retires without a forged health-break explosion, sound, debris or killing type. Zero/negative-factor and protected override contracts remain core-tested.
- A lamp behind a wall receives no covered blast/bullet hit; nearest prop can shield an NPC for hitscan once the model adapter exists. Direct rocket-to-prop impact is a separate required test, not implied by nearby blast success.
- Repeated preparation of the same frame produces no duplicate break/audio/debris; tombstones survive next render, collision lookup, attachment rebuild and level close.
