## RFDS comparison and full-SP obligations

Current RFDS already has the right **separate owners**: RGCH committed cutters,128 admission records with adjusted centers/vectors/scale plus packed requested centers, fixed codec bounds, orientation RNG, and retained noise maps/seeds/packing cursor/RNG. A later port CSG rejection can leave admission history/RNG advanced while RGCH remains unchanged. Save all those fields as they stand; do not truncate admissions to committed count, filter duplicates retroactively, or regenerate RNG from successful geometry. A failed-cut regression must compare the next blast after reload with uninterrupted play, not only the current mesh.

What full SP integration needs beyond the present DEV successful-terrain path:

1. **Stable room/template identity per admission and pending cut.** Original32-byte record distinguishes template and room, flags, orientation/direction, requested center and scale. Current DEV admission records assume one template/room; RGCH retains successful cutter geometry but cannot reconstruct a pending or rejected attempt's missing descriptor. Add these only when multi-room/template gameplay actually arrives; do not silently assign room0.
2. **Explicit save barrier for pending destruction.** The first playable SP policy should finish any admitted in-flight geometry job and resource bake before snapshot, or fail/defer save without losing the request. If saving during processing is required, serialize the ordered pending descriptor queue and associated RNG/room/template/flags; committed geometry alone cannot represent it. The current port cut is synchronous, so do not add a queue merely to imitate original internals. Integrate the barrier with whatever async work actually exists.
3. **Admission-only failure coverage.** Exercise save after duplicate rejection, admission accepted but CSG budget/capacity failure, and presentation failure after geometry commit. Require unchanged/advanced counts and RNG according to actual mutation point, retained failed-admission influence on duplicate/shallow checks, and identical next accepted edit. These are missing cases in current PC checkpoint workflow despite ordinary empty/repeated/shallow/reset/next-blast coverage.
4. **Retained noise ownership independent of faces.** Keep unused maps, original seed chain and next allocation cursor; don't derive map count from current visible faces or reseed on load. Current RFDS does this. This report's snapshot slice does not prove original full save persists noise maps or CRT RNG; do not claim RFDS is original-save compatible. Current explicit per-owner RNG persistence is a port consistency policy.
5. **Restore before player/contact/world activation.** Terrain, collision overlay and all room identities must exist before placing restored actors or replaying triggers. Coordinate player/AI/mover/projectile state with their owners; a saved hole without the actor/body/world state using it is not a full save. Destruction transient debris/projectile effects may be intentionally omitted only under a documented settled-save policy.

No new format implementation is proposed in this audit. Immediate useful test is an admission-only failed cut -> RFDS -> fresh restore -> same next input comparison. Native disk transport/pure validation remains the separate current integration work.
