# NPC grenade attacks

Enemy grenade attacks now launch into an eight-projectile pool rather than falling through to generic instant-hit damage. A successful launch consumes one reserve grenade, retains shooter handle and AI-scaled damage, and advances attack cadence/presentation. A failed trajectory or full pool retries without consuming ammo; empty ordinary actors can use existing weapon fallback. Accepted launch timing is first-pass policy, not an authored animation marker. Explicit Attack orders retain the existing fallback restrictions.

A low ballistic arc uses authored speed and gravity; unreachable trajectories are rejected. Flights update independently of the throwing NPC, bounce through the shared sweep, detonate on fuse expiry, render the existing grenade model, and use shared blast/terrain effects. Explosion damage now accepts source/kind explicitly; old player explosion callers retain their original wrapper. Active flights block scoped checkpoint admission. Resource loading currently restricts this path to the developer room; campaign grenade actors no longer fall through to fake hitscan when their projectile resources are unavailable.

DEV_NPC3 selects the existing guard seed, equips three grenades and alerts it after startup clearing. PC RF_REPLAY_DEV_NPC=3 and Xbox dev-npc.flag byte3 use the same fixture. xemu_render_check.py --npc-grenade-test packages it and compares AI_GRENADES counters. This is explicit test staging, not an authored campaign loadout.
